1. 환경 세팅
- WSL 환경에 Go, subfinder, httpx, jq 설치
- Burp Suite로 프록시 인터셉트 구성

2. 계정 생성
- 대상 서비스가 Cloudflare Turnstile 캡차를 사용 중이었는데, 로컬 프록시 켜진 상태에서 캡차 검증이 계속 실패하는 현상을 확인함 → 프록시를 끄고 순수 브라우저로 재시도해 해결함
- 이메일 인증 완료 후 계정을 생성한 후 신원인증 단계는 미완료로 두고 로그인 플로우 테스트를 진행함

3. 로그인 폼 SQL Injection 테스트
- 로그인 API 엔드포인트를 Burp로 캡처
- 아래 페이로드로 인증 우회 및 에러 기반 SQLi 여부 테스트:
    - `'` (단일 quote)
    - `' OR '1'='1`
    - `' OR '1'='1'--`
    - `' AND SLEEP(5)--` (시간 기반)
- 결과: 앞의 3개는 401 Unauthorized 응답 → parameterized query 사용 추정. SLEEP 기반 페이로드는 WAF에 403으로 차단됨
- 결론: 로그인 폼에서 SQLi 취약점은 발견하지 못함

4. Recon
- 대상 도메인에 subfinder/httpx 실행 → 서브도메인 및 살아있는 호스트 다수 확인
- API 문서 사이트, 인증 서버, staging/sandbox 서브도메인 등을 식별
- 메인 도메인은 Angular SPA로 확인, WordPress 기반 아님

5. 스코프 확인 이슈
- HackerOne 프로그램의 Structured Scope 테이블이 비어있는 상태를 확인
- CSV export도 데이터 없이 헤더만 존재
- Program Guidelines 페이지에도 구체적인 in-scope 도메인 목록이 명시돼 있지 않음
- 현재 상태: 스코프가 불명확해 추가 테스트를 보류하고, 프로그램 운영진에게 문의 후 진행 여부를 결정할 예
