## 1. 개요 및 스코프 (Executive Summary & Scope)

본 보고서는 대상 자산 그룹에 대한 웹 애플리케이션 공격 표면 식별(Attack Surface Mapping) 및 주요 후보 엔드포인트에 대한 가hypothesis(가설) 기반 취약점 검증 경과를 정리한 내용입니다.

* **진단 범위:** 메인 서비스 REST API 패브릭, SSO(Single Sign-On) 게이트웨이 연동 구간, 서브/내부 서비스 백엔드 API
* **주요 목적:** 미인증 접근 경로, SSRF/오픈 리다이렉트 및 오염 가능 파라미터, 인가 우회(IDOR) 가능성 검증

---

## 2. 수집 데이터 분석 및 공격 표면 지도 (Attack Surface Mapping)

수집된 엔드포인트 데이터(REST API 인덱스, 대용량 JS 경로 로그 등)를 분석하여 다음과 같이 4가지 주요 공격 영역(Vector)을 분류하였습니다.

```
[공격 표면 분류 Map]
├── Vector A/B: SSO Gateway & Redirect Behavior (NetIQ/Novell Access Manager)
├── Vector C  : Token-based Microservice (Entropy/IDOR Assessment)
└── Vector D  : Custom WordPress REST API Framework (`/vip/v1/*`)

```

### [Vector A/B] SSO 게이트웨이 연동 및 리다이렉션 흐름

* **대상:** SSO 프론트엔드 게이트웨이 (`[SSO-GW-HOST]/nesp/app/plogin`)
* **특징:** 인증 처리 후 `target=` 파라미터를 통해 리다이렉트를 유도하는 구조 식별.
* **가설:** 외부 도메인 허용 시 Open Redirect 및 인증 흐름을 악용한 피싱 연계 가능성.

### [Vector C] 서비스 토큰 및 인가 파라미터 패턴

* **대상:** 라벨/서비싱 백엔드 API (`[API-HOST]/return-label-service/...`)
* **특징:** 요청 파라미터 내 `crypto=` 형태의 인코딩된 토큰 값 복수 식별.
* **가설:** Base64 URL-safe 규격 토큰의 구조적 난수성(Entropy) 부족 시 시퀀스 추측 및 IDOR 취약점 존재 가능성.

### [Vector D] WordPress REST API 커스텀 네임스페이스

* **대상:** WP REST API 커스텀 라운드트립 (`/wp-json/vip/v1/*`)
* **특징:** 개발자/커스텀 플러그인에 의해 정의된 엔드포인트(`dev-tools` 등) 존재. URL 파라미터 입력 시 서버 단 Allowlist 검증 동작 확인 (`"url is not a valid allowed URL"`).
* **가설:** 동일 개발 주체가 구현한 형제 엔드포인트(Sister Endpoints) 내 파라미터 검증 누락 가능성.

## 3. 세부 검증 수행 및 결과 (Technical Verification & Results)

### [검증 대상 1] SSO 게이트웨이 (`target=` 파라미터) 리다이렉션 검증

외부 도메인 리다이렉트 수용 여부 및 파싱 에러 발생 패턴을 확인하기 위해 차분 요청(Differential Request) 테스트를 진행하였습니다.

#### 수행 테스트 조건 및 응답 패턴

1. **외부 도메인 입력:** `GET /nesp/app/plogin?target=https://[EXTERNAL-DOMAIN]/`
2. **내부 도메인 입력:** `GET /nesp/app/plogin?target=https://[INTERNAL-DOMAIN]/`
3. **파라미터 미포함:** `GET /nesp/app/plogin`

#### 검증 결과 분석

* **응답 규격:** 모든 조건에서 동일한 **HTTP 500 Internal Server Error** 및 동일 크기(154 Bytes)의 정적 에러 응답 반환.
* **응답 헤더 분석:** `Via: Access Gateway` 헤더를 통해 NetIQ/Novell Access Manager 게이트웨이가 전단에 위치함을 확인.
* **판정:** `target` 파라미터 값의 유효성 파싱으로 인한 예외가 아닌, 해당 엔드포인트 자체가 선행 세션/인증 컨텍스트가 결여된 단독 GET 요청을 거부하는 구조임. **(오픈 리다이렉트 미성립, 해당 벡터 식별 완료 후 종료)**

## 4. 향후 추진 계획 (Roadmap & Next Steps)

```
[우선순위 진행 로드맵]
1. [High Priority] Custom REST API Namespace 전체 라우트 맵핑 (`/vip/v1/*`)
   └── 동일 프레임워크 내 검증 누락 엔드포인트 탐색
2. [Medium Priority] `crypto=` 토큰 패턴 및 난수성(Entropy) 분석
   └── 토큰 구조 해독 및 타임스탬프/사용자 식별자 포함 여부 검증

```

1. **커스텀 REST API 엔드포인트 전수 조사:**
* `/wp-json/` 전체 라우트 인덱스 중 동일 네임스페이스 (`/vip/v1/`) 하위 라우트 전체 추출.
* 입력값 검증 미비 또는 인가(Authorization) 처리가 누락된 내부 유틸리티 라우트 탐색.


2. **서비스 토큰 무작위성 검증:**
* 수집된 `crypto=` 파라미터 토큰 샘플의 디코딩 구조 분석(Base64/Bitwise).
* 토큰 생성 알고리즘의 예측 가능성 및 무단 액세스 가능성 검증.
