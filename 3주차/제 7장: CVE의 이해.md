## CVE 정의 및 목적, 이해 및 활용, 실습

### CVE 정의

- CVE는 Common Vulnerabilites and Exposures의 약자
- CVE는 공개적으로 알려진 컴퓨터 보안 결함에 대한 목록
- 각각의 CVE는 고유한 ID 번호가 부여되어 특정 보안 결함을 명확하게 식별할 수 있게 함
    - CVE-발견번호-고유번호

### CVE 목적

- CVE는 IT 전문가들이 컴퓨터 시스템의 보안 결함을 우선순위를 정하여 해결하는 데 도움을 주는 표준화된 방법을 제공
- CVE는 보안 결함에 대한 공통의 언어를 제공하여 서로 다른 시스템과 데이터베이스 간에 보안 위협 정보를 쉽게 공유하고 이해하는 데 도움을 줌
- CVE는 보안 결함이 공개되고 이를 해결하기 위한 조치가 취해질 때까지의 과정을 추적하고 문서화하는 역할을 함

### CVE 조건

- 독립적으로 수정 가능해야 함
    - 다른 버그로부터 독립적으로 수정할 수 있는 결함
- 영향을 받는 공급자에 의해 인정되거나 문서화되어야 함
    - 소프트웨어 또는 하드웨어 벤더가 버그를 인정하고, 이것이 보안에 부정적인 영향을 미친다는 것을 인정해야 함
    - 보고자는 버그의 부정적인 영향을 입증하고, 이것이 영향 받는 시스템의 보안 정책을 위반하는 취약점 보고서를 공유해야 함
- 하나의 코드베이스에 영향을 미쳐야 함
    - 둘 이상의 제품에 영향을 미치는 결함은 별도의 CVE를 받음
    - 공유 라이브러리, 프로토콜 또는 표준에서 발생하는 취약점은, 그 취약점이 존재하는 코드를 사용하지 않아도 되면 단일 CVE를 받음
    - 그러나 해당 취약점이 존재하는 코드를 사용하지 않을 수 없는 경우, 각각의 영향 받는 코드베이스나 제품은 고유의 CVE를 받음

### CVE 취약점을 이용한 버그헌팅 전략

1. 서드 파티 시스템 발견
2. CVE 취약점 이용 가능 확인 후 로컬 테스트
3. CVE Exploit

### 버그헌팅 시 CVE 취약점 활용의 장단점

#### 장점

- 빠른 시간 내에 취약점을 찾을 수 있음
- 공개된 취약점이기 때문에 취약점에 대한 내용을 쉽게 찾아볼 수 있음
- 신규 취약점 발굴에 도움됨

### 단점

- 중복된 리포트 제보가 있을 가능성이 높음
- 이미 잘 알려진 취약점이기 때문에 이미 패치가 되었을 가능성이 높

### Metasploit

- 대표적인 Pentesting framework
    - CVE에 등록된 보안 취약점을 이용하고 테스트하는 도구
    - Recon, Scan, Exploit 등 다양한 스텝에서 사용 가능
    - 버그헌팅이나 모의헌팅에서 자주 활용
    - Kali Linux에 기본 탑

### 취약점 및 공격 기술 서칭

search (Metasploit Framework) vs searchsploit (Exploit Database)

### 취약점 익스플로잇

exploit (공격 실행) vs run (정보 수집, 서비스 스캔, DOS 공)
